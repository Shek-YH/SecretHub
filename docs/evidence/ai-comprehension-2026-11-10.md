# AI 理解度测试（2026-11-10）

方法：用 organize_fixture（假数据）跑“AI 整理导入 → 导出”，得到带注释的 `.env.example`（只有变量名和注释，无任何值）。只把这份文件交给一个 Haiku 5.5 子代理，不给其他上下文，要求它说明每个变量、写 SSH 连接代码和通义千问调用代码，并列出含糊之处。

## 结果
- 26 个变量的用途和所属服务器/服务全部判断正确。
- 写出的 ssh2 连接代码（私钥优先、没有私钥时用密码）和 OpenAI 兼容方式调用通义千问的代码都正确，只用了变量名。

## 提出的 13 条疑问及处理
| 类别 | 疑问 | 处理 |
|---|---|---|
| 导出注释缺失 | QWEN_MODEL、DASHSCOPE_BASE_URL 没有说明 | 已修：API Key 的模型行和地址行分别加注释“调用的模型名”“接口基础地址” |
| 格式不明 | 私钥在 .env 里是 `\n` 转义还是 base64；白名单的分隔方式；URL 是否带版本前缀；同时有密码和私钥时以哪个为准 | 已修：secrethub-import skill 要求 AI 在变量说明里写清格式 |
| 资料本身缺失 | OSS 缺 AccessKey；阿里宝塔面板缺用户名和密码；私钥口令（passphrase）；SSH 用户的权限 | 按设计不在导出阶段处理：调用失败时由 AI 向用户索取 |
| 命名不统一 | API_SK 与 API_TOKEN | 来自原始资料；AI 整理时可统一命名（属于 skill 层面的改进，暂不强制） |
