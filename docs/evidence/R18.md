# R18 Export Semantics, Selection and API Validation Evidence

- Model IDs and environment variable names are separate. Historical invalid model Env Keys such as `DEEPSEEK-V4.1-FLASH` fall back to a provider-derived valid key such as `DEEPSEEK_MODEL`.
- `.env` output contains only project Env pairs and optional `#` remarks. SecretHub-only fields (value type, category, scope, tags, name and provider display metadata) are not serialized.
- “Copy all” reuses the same project Env renderer as export, so it copies Env pairs and remarks only; it does not copy SecretHub management metadata.
- The toolbar “Select visible” action selects all current filtered results and “Clear selection” removes those visible IDs without disturbing selections outside the current filter.
- One-click validation uses fixed HTTPS Provider model-list endpoints, bounded native requests and provider-specific auth headers. It persists only `valid`, `invalid`, `unauthorized`, `rate_limited`, `network_error` or `unsupported` status; response bodies and keys are not logged or returned to WebView.
