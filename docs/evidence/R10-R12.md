- MCP TypeScript: `npm test`, `npm run typecheck`, `npm run build`, `npm run smoke` and `npm audit --audit-level=high` all pass.
- MCP stdio smoke uses a synthetic SQLite database and exercises `initialize`, `tools/list` and `tools/call`; the returned catalog item contains `hasValue` but no `value`, `ciphertext` or payload bytes.
- CLI runtime injection: `cargo test -p secrethub-cli` covers `--secret-id` parsing and `.secrethub.toml` parsing; child processes are started directly with `Command`, never through a shell.
- Import: `.env` and flat JSON parsing validate env keys and only permit string/number/boolean JSON values; Tauri preview returns env keys only, confirmed import encrypts in Rust.
- V4 bridge: MCP `prepare_project_env` / `apply_profile` queue a JSON plan containing only request ID, project path and Secret IDs; Tauri lists pending plans and confirmation invokes `export_env`, then removes the plan. MCP protocol smoke verifies the queue contains no payload bytes.
- V1 classification: storage/core tests verify `value_type`, `category`, `scope`, `favorite`, and `archived`; the desktop list exposes category/status/favorite/archived filters without indexing Secret values.

## Open acceptance boundary

`secrethub_prepare_project_env` and `secrethub_apply_profile` deliberately return a confirmation-required plan. The Desktop bridge consumes pending plans and routes confirmed requests through the existing masked preview/Git/path-safe export path; MCP itself never writes project files.

## V3.5 proxy boundary

`crates/proxy` tests pass for hashed short-lived tokens, revocation, expiry, fixed HTTPS Provider origins and SSRF rejection. `apps/proxy` is wired to interactive Rust Vault unlock and bounded HTTP forwarding; a real Provider sandbox smoke remains pending because no test credential is configured.

The current V3 runtime path is the CLI direct-child injection (`secrethub-cli run -- ...`); `apps/proxy` now provides the bounded HTTP forwarding process on top of the verified proxy policy foundation.

`cargo test -p secrethub-proxy-http` covers bounded HTTP parsing, unsupported-method rejection and missing-token rejection before upstream contact. The forwarding binary is built; real-provider forwarding remains `WAITING_USER` and requires a credential entered locally, never pasted into chat.
