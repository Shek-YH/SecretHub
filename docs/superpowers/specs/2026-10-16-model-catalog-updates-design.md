# 模型目录更新与下发设计

> 状态：已确认（2026-10-16）。§9 决策 2–4 采用推荐方案；决策 1（托管位置）待定，开发期使用占位地址。按 §8 交给 Sonnet 实现。
> 前置：模型能力路由 P1/P2（S1–S6）已完成；每个 Key 检测时会同步服务商的真实模型清单（`provider_models`）。

## 1. 问题

厂商持续发布新模型（例如 DeepSeek 新版本），程序内置的 `packages/provider-definitions/providers.json` 里的默认模型很快过时。

但它影响的范围有限：

| 用途 | 是否受目录过时影响 |
|---|---|
| 用户实际能调用哪些模型（`find_models`、审核写入） | **不受影响**：来自每个 Key 实时同步的 `/models` 清单 |
| 添加 Key 时下拉框里的默认模型 | 受影响 |
| 同步结果缺少能力信息时的能力标签（catalog 来源） | 受影响 |
| 服务商官网链接、接口地址、协议 | 很少变化，变了必须随正式版本发布 |

## 2. 目标与非目标

**目标**
1. 用户检测过 Key 后，下拉框直接显示这个 Key 的真实模型，不依赖内置目录。
2. 维护者（你）借助 AI 定期整理新模型资料，审核后发布一个**签名的模型目录数据文件**；用户的程序自动获取并使用，无需重装。
3. 远程文件被篡改或服务器被入侵时，最坏后果也只是"默认模型名推荐不准"，**不可能把用户的 Key 引向别的地址**。

**非目标**
- 爬取厂商官网页面。
- 由终端用户的 AI 修改程序。
- 安装包自动升级（Tauri updater），以后单独做。

## 3. 三层分工

| 层 | 内容 | 更新方式 | 谁负责 |
|---|---|---|---|
| L1 实时同步（已有） | 某个 Key 实际能用的模型 | 用户点检测 / 同步模型 | 程序自动 |
| L2 远程模型目录（新增） | 每个服务商的模型名称、默认模型、能力标签、是否下线 | 程序启动时和每 24 小时拉取签名文件 | 维护者发布 |
| L3 应用版本 | 服务商增删、接口地址、官网链接、协议、代码 | 安装新版本 | 维护者发布 |

## 4. 下拉框优先使用同步清单（U1）

- 编辑一个已同步过的 API Key 时，模型下拉框按顺序显示：
  1. 该 Key 同步到的模型，带能力标签，按"内置目录里的默认模型在前、其余按名称"排序；
  2. 内置目录或远程目录中有、但同步清单里没有的模型，归到"目录推荐（未在此 Key 清单中）"分组；
  3. "自定义模型 ID"。
- 新建 Key 时还没有清单，保持现状。保存后会自动检测并同步，之后再编辑就会显示真实清单。
- Key 详情的"可用模型"列表中，每行加一个"设为默认模型"按钮，点击后把该模型写入这个 Key 的 `model_id`，模型变量名不变。

## 5. 远程模型目录（L2）

### 5.1 文件格式

`model-catalog.json`：

```jsonc
{
  "schema": 1,
  "serial": 2026101601,          // 单调递增整数，防回滚
  "publishedAt": "2026-10-16T12:00:00Z",
  "providers": {
    "deepseek": {
      "defaultModel": "deepseek-v4.1-flash",
      "models": [
        { "id": "deepseek-v4.1-flash", "label": "DeepSeek V4.1 Flash", "capabilities": ["chat"] },
        { "id": "deepseek-v4-flash", "deprecated": true }
      ]
    }
  }
}
```

（示例中的模型 ID 只是格式示意，实际以维护时核实的结果为准。）

- **字段白名单**：只允许 `id`、`label`、`capabilities`、`deprecated`、`defaultModel`，出现其他字段（尤其任何 URL）时整个文件拒绝。
- `providers` 的键必须是程序内置 `providers.json` 里已有的服务商，未知服务商忽略。远程文件不能新增服务商。
- 能力取值必须在能力词表内；模型 ID 1–200 字符、不含控制字符；每个服务商最多 300 个模型；文件不超过 1 MB。

### 5.2 签名与防回滚

- Ed25519 分离签名：`model-catalog.json.sig`（base64）。
- **公钥**编译进程序（`packages/provider-definitions/catalog-public-key.txt`）；**私钥**只由维护者离线保管，不进仓库、不上传服务器。
- 程序只接受签名正确且 `serial` 大于当前已用 serial 的文件。
- 程序内置一个 `catalog-serial`（随版本发布）。安装了更新的版本后，若本地缓存的远程文件 serial 更旧，则忽略缓存。
- 私钥丢失时，发布一个带新公钥的程序版本。

### 5.3 获取与缓存

- 地址在构建时固定（环境变量 `SECRETHUB_CATALOG_URL`，默认值待定，见 §9）。必须是 HTTPS，不跟随重定向，超时 10 秒。
- 获取时机：程序启动时一次，此后每 24 小时一次；设置页提供"立即检查更新"按钮，并显示当前目录 serial 和发布时间。
- 设置项"自动更新模型目录"默认开启，可关闭。
- 验证通过后缓存到应用数据目录 `catalog/model-catalog.json` 和 `.sig`。启动时重新验证缓存，断网也能用。
- 获取不涉及任何 Key，也不携带用户信息（不带 Cookie，不带标识）。

### 5.4 合并规则（"生效目录"）

- 对远程文件中列出的服务商：用远程的 `models` 列表**整体替换**内置列表（这样下线的模型能被移除）；`deprecated: true` 的模型不在下拉框推荐，但能力标签仍可供推断使用。
- `defaultModel` 决定下拉框的默认项和排序。
- 未列出的服务商沿用内置数据。
- 接口地址、官网链接、协议、环境变量名**始终来自内置数据**。

### 5.5 使用方

- **Rust**：`infer_capabilities` 的 catalog 来源改为读生效目录；新增命令 `catalog_effective()` 返回给前端。
- **前端**：Tauri 模式下用 `catalog_effective()` 生成服务商模板；演示/测试模式仍用静态 import。
- **MCP**：Desktop 每次生效目录变化时，写出 `catalog/effective-models.json`（只含模型数据）。MCP 读取它；读不到时回退到内置 `providers.json`。MCP 不重复验签，因为该文件位于和 vault 同一个本地目录，信任级别相同。

## 6. 维护者工作流

1. 运行维护 skill `skills/secrethub-catalog-maintainer`：
   - AI 按 `providers.json` 逐个服务商核对官方文档或官方模型列表页（只用公开资料，不需要任何 Key），对比 `packages/provider-definitions/model-catalog.json`。
   - 输出变更清单表：服务商 / 新增 / 下线 / 默认模型变更 / 能力标签变更 / 来源链接。
2. 你审核并确认后，AI 修改 `model-catalog.json`、递增 `serial`，运行 `npm run catalog:check`（校验格式、白名单、服务商存在、能力词表）。
3. 你在本机运行 `npm run catalog:sign`（私钥路径从环境变量读取），生成 `.sig`。
4. 把 `model-catalog.json` 和 `.sig` 上传到服务器。
5. 发布新版本程序前，运行 `npm run catalog:bake`：把远程目录合并进内置 `providers.json` 并更新内置 serial，新用户安装后即为最新。

首次使用前运行一次 `npm run catalog:keygen` 生成密钥对：公钥提交到仓库，私钥自行离线保管（例如存进密码管理器）。

## 7. 安全要点

| 风险 | 对策 |
|---|---|
| 服务器被入侵，攻击者替换目录文件 | 必须有私钥签名才会被接受；文件结构上不允许任何 URL 字段，最坏情况只是推荐的模型名不准 |
| 旧文件回放 | `serial` 单调递增，并与内置 serial 比较 |
| 模型名中的恶意字符串 | 长度和字符校验；界面只按纯文本渲染 |
| 私钥泄露 | 发布带新公钥的版本；私钥永不进仓库（`.gitignore` 加规则，`catalog:sign` 拒绝读取仓库内路径） |
| 隐私 | 获取请求不带任何 Key、Cookie 或用户标识 |

## 9. 待确认的决策

1. **文件托管位置**：可选 GitHub Releases、阿里云 OSS + CDN，或自己的云服务器。国内用户多的话推荐 OSS/CDN。C3 实现时可以先用占位地址，不阻塞开发。
2. **自动更新默认开启**，可在设置里关闭。推荐开启。
3. **远程模型列表整体替换内置列表**（而不是追加合并），以便移除下线模型。推荐整体替换。
4. **MCP 读取 Desktop 写出的生效目录**，不自行验签。推荐这样做。
